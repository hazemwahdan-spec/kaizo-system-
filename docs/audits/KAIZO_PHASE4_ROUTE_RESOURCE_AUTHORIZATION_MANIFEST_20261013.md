# KAIZO Phase 4 — Source-Derived Route/Resource Authorization Manifest

Date: 2026-10-13
Candidate branch: `feat/phase4-core-resource-authorization`
Purpose: turn the current source-level route inventory into an explicit closure backlog. This is a source-derived manifest, **not** proof that each route is secure or deployed.

## Global closure rule
- Identity authentication is necessary but not sufficient.
- A route is not PASS until its exact persisted resource, parent chain, tenant, actor role, consent applicability, audit event, and negative tests are explicit.
- Mounted/generated routes have a shared fail-closed backstop, but that backstop does not prove route-specific ownership.
- Generated feature routes (`/api/v1/features/{feature_id}/{slug}` POST/GET and `/api/v1/features/{feature_id}/{slug}/{record_id}` GET) intentionally deny non-test principals until feature-record tenant/subject/actor binding is authoritative and tested.
- `GET /api/v1/health` is the only public Core health exception. Governed commercial product routes have a separate policy and are outside this Core resource manifest.

## Status vocabulary
- `CORE_GUARDED / RETEST_REQUIRED`: direct Core route has a specific guard in the candidate; exhaustive route-specific independent retest remains open.
- `MOUNTED_GENERIC_GUARD / NOT_PROVEN`: shared guard attached, but exact parent/role/consent/audit contract remains incomplete; fail closed where no recognized persisted scope resolves.
- `SHARED_POLICY_BLOCKER`: global/shared catalog or ingest route needs explicit global-vs-academy ownership and publisher/role policy.
- `PUBLIC_HEALTH`: public health only; not a resource authorization route.
